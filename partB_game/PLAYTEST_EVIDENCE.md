# Playtest evidence (TEAM: COMPLETE THIS BEFORE SUBMITTING)

The rubric asks for "a few peers tried it, with feedback or outcomes". This file is a template: **do not invent results**. Run 3-5 real playtests, fill the tables, and attach screenshots or the exported session summaries.

## How to run a playtest (10-15 minutes each)
1. Give the player `MachineWhisperer3D.html` (or a GitHub Pages link) and **no explanation** beyond "get a good score".
2. **Before playing**, ask the three pre-questions below and write their answers down.
3. Watch silently. Note where they get stuck.
4. **After playing**, ask the same three questions again, then the feedback questions.
5. Ask them to open the field manual (book icon, top right), press **COPY SESSION SUMMARY**, and paste it under their row.

## Pre / post questions (same wording both times)
Q1. A model scores 100% on the data it learned from. Does that prove it works on new data? Why or why not?
Q2. Only 1 in 20 machines fails. A model that says "nothing will fail" is 95% accurate. Is it a good model?
Q3. A column in your data is only filled in after a machine fails. Should the model use it to predict failures?

(Intended answers: no, it may have memorised; no, it catches zero failures, so check recall/precision; no, it would not exist at prediction time = leakage.)
